# configx 标准

**crate**：`configx` v0.1.1 · 依赖：`thiserror`、`serde`、`serde_json`、`toml`

## 1. 定位

configx 提供线程安全的分层配置存储：把内存 / 环境变量 / `KEY=VALUE` 文件等配置源按注册顺序合并成一份不可变快照，并对外提供读取、类型化读取、差异比较、变更订阅与密钥脱敏。它是纯同步 crate，不实现分布式配置中心、schema 推导、远端 secret manager 或自动文件监听。

## 2. 数据与键治理

- 键大小写敏感、按原样存储，不做规范化；只拒绝空键、含控制字符的键与超过 512 字节的键。
- 快照为 `Arc<BTreeMap<String, String>>`：不可变、可廉价克隆、按键有序。
- 后注册源覆盖先注册源（`LayeredConfig` 合并语义）；`reload` 失败时快照与变更序号保持原样（失败不改状态）。
- 脱敏是展示层职责：`is_secret_key` / `redact_value` / `redact_map` 只用于 `Debug` 与日志路径，`get` 永远返回原始值。

## 3. 并发与订阅

- 单写多读：读取 `&self` 可并发；`reload` / `register_source` 需要 `&mut self`。
- 变更通知基于 `Condvar`（`ConfigWatch` / `ConfigSubscription`），不引入异步运行时，不启动后台线程或文件 watcher。
- `generation` 单调递增，订阅者以变更序号判断是否需要重读快照。

## 4. 配置治理

- `ConfigxConfig`：结构体 + `builder()` / `from_env()` / `from_toml()` + `validate()`，校验失败 fail-fast。
- 环境变量开关：`ENV_REDACT_SECRETS`、`ENV_ALLOW_EMPTY_SNAPSHOT`、`ENV_GLOBAL_FILE`（见 `config` 模块常量）。
- 秘密值不进入配置仓库明文；只经环境变量或内存源注入，日志路径统一脱敏。全局文件不得包含 `secret:` 前缀键。

## 5. 验收

```text
cargo fmt --all --check
cargo test --all-targets
cargo clippy --all-targets -- -D warnings
```

测试至少覆盖：多源合并与覆盖顺序、键校验边界（空键 / 控制字符 / 512 字节）、reload 失败不改状态、类型化读取错误路径、差异比较有序性、订阅通知与超时等待、脱敏纯函数、公开 API 面（`tests/public_api.rs`）。

基准：`benches/hot_path.rs`（`harness = false`，离线）覆盖 reload → snapshot → get_typed → diff → validate 热路径；`cargo bench --bench hot_path -- --quick` 用于快速冒烟（`cargo test` 以 `--test` 模式运行时自动缩减为 10 次迭代）。

## 6. 全局配置文件

- 至多一份可选的 `KEY=VALUE` 全局文件源（`GlobalFileSource`）。构造存储**不会**自动读取家目录；调用方解析路径后显式 `register_source`。
- 路径解析：优先 `ENV_GLOBAL_FILE` 非空值；否则 `{XDG_CONFIG_HOME}/{app_id}/config`，再否则 `{HOME}/.config/{app_id}/config`；再否则解析失败。`app_id` 不得为空、不得含控制字符 / 路径分隔符 / `..`、不得超过 64 字节。
- 文件不存在视为该源贡献 0 键且成功。文件存在但不可读、键非法、或含 `secret:` 前缀键：`reload` 失败且不改状态。
- 覆盖仍是后注册覆盖先注册。不创建、不改写、不监视文件。不提供多文件目录发现、深表合并、CLI 或应用 schema。
- `FileSource` 对缺失路径仍失败；与全局源缺文件为空不是同一语义。
